    The problem

    Contributing is hard. Reviewing is harder.

    Beginners cannot tell what a repository expects, which issue is safe, or what "ready" means. Maintainers pay for that confusion with unwanted, low-quality and bulk-generated pull requests. ContribSutra reduces both costs.

    Understand the repo

    Policies, license, toolchain, CI and contribution rules, each with a file and line number and a SHA-256.

    Pick the right issue

    A transparent shortlist that declines closed, assigned, security-related and instruction-injected issues, and says why.

    Learn, do not copy

    Six small steps with hints and acceptance checks in three modes. The plan never writes your solution.

    Honest PR packet

    Verified, user-reported, inferred and not-run claims stay separate. Your "tests passed" is never promoted to verified.

    Independent audit

    30 adversarial checks, expected versus observed, with negative controls. HTML, Markdown and JSON, sealed with SHA-256.

    Offline and read-only

    No network, no API key, no telemetry. It never opens a PR, comments, assigns or runs repository scripts.

    How it works

    From a cloned repo to a respectful pull request

    Every step is read-only and produces a sealed report. The last step belongs to you.

    1. 1

      Understand

      Scan the repo and check your tools.

      contribsutra scan --root ./repo
    2. 2

      Choose and learn

      Rank issues, then plan small steps.

      contribsutra issues --issues issues.json
    3. 3

      Prepare

      Build an honest PR packet and audit it.

      contribsutra pr-check --root ./repo

    Who is in control

    The tool stops at planning

    Nine lifecycle states. ContribSutra can help up to planning. Authorising work, running tests, reviewing the diff and submitting are human-only.

    FAQ

    Quick answers

    Is this a bot or an AI that writes my pull request?

    No. It prepares you and your reviewer. You write the change and you decide whether to submit.

    Does it need an API key or internet?

    No. It uses only Node.js built-ins and makes no network calls.

    Why was a "good first issue" declined?

    Labels go stale. The issue may be closed, assigned, locked, security-related, very large, or contain instruction-like text. The reason is printed next to it.

    Why does my passing test show as "unverified"?

    ContribSutra did not run it. The label tells the reviewer what to trust. Attach the captured output.

    Does it work in my IDE?

    The skill files are copied and tested. Whether your IDE activates them has not been verified. The CLI works wherever Node.js 22+ does.

    Is the audit third-party certification?

    No. It is a reproducible self-assessment generated by the tool it audits. Every report lists what was not tested.
