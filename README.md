ContribSutra AI is an **offline, keyless command-line tool and a set of 25 portable agent skills** that help a first-time open-source contributor answer six questions honestly:

1. *What is this repository, and what does it expect from contributors?*
2. *Can my machine run it?*
3. *Which issue is actually suitable for me, and which ones should I leave alone?*
4. *What is a small, learnable first change?*
5. *What did I really test, and what did I not?*
6. *Am I ready to ask a maintainer for a review?*

It is built to **teach contributors and protect maintainers**: it never opens a pull request, never comments, never assigns an issue, never runs a repository's scripts, and never claims a test passed that it did not run. It is not a PR-generating bot and will not become one.

> Created by **Vatsal Shah**. Apache-2.0. Works with Claude Code, Cursor, Codex, GitHub Copilot, Gemini CLI, OpenCode and any tool that reads `AGENTS.md`.

## Try it in 30 seconds

```bash
npx contribsutra-ai --version
npx contribsutra-ai audit --out ./contribsutra-audit
```

`audit` writes an **independent audit report as HTML, Markdown and JSON** (plus `SHA256SUMS.txt`). Open `contribsutra-audit/audit-report.html` in a browser. It runs 30 adversarial safety checks against the real code and shows each *expected* versus *observed* result.

To look at a real repository you cloned yourself:

```bash
npx contribsutra-ai scan --root ./some-repo --out ./reports/scan      # policies, license, toolchain, file hashes
npx contribsutra-ai doctor --root ./some-repo                          # are the declared tool versions installed?
npx contribsutra-ai issues --issues ./issues.json --skills docs,python --out ./reports/issues
npx contribsutra-ai plan --root ./some-repo --issues ./issues.json --issue 101 --out ./reports/plan
npx contribsutra-ai pr-check --root ./some-repo --issue 101 --out ./reports/pr
```

Export an issue snapshot with the official GitHub CLI yourself, then give the file to ContribSutra (it never calls GitHub):

```bash
gh issue list --repo OWNER/REPO --state open --limit 100 --json number,title,state,labels,assignees,updatedAt,body > issues.json
```

## What you get

| Command | What it does | Evidence |
|---|---|---|
| `scan` | Maps README, CONTRIBUTING, LICENSE, conduct, security, templates, CODEOWNERS, manifests (Node/Python/Rust/Go), CI workflows, documented commands, and policy signals (DCO, CLA, AI-assistance, discuss-first) with `file:line` sources and SHA-256 | Verified local hash + labelled heuristics |
| `doctor` | Fixed, bounded `--version` probes; compares them with the versions the repo *declares* | Observed versions only |
| `issues` | Ranks an issue snapshot with reasons; **declines** closed, assigned, locked, security-sensitive, prompt-injection and large-scope issues; flags duplicates, stale and under-specified issues | Offline snapshot, not live GitHub |
| `plan` | Six small learning steps, with hints, acceptance checks and human review points; three modes (`guided`, `collaborative`, `self-directed`) | `PLANNED_NOT_EXECUTED` |
| `pr-check` | A PR packet that keeps *verified*, *user-reported*, *inferred* and *not run* separate, plus a draft description you rewrite yourself | Test claims stay `unverified_external_claim` |
| `verify` / `render` | Detects tampered reports; renders sealed JSON to Markdown/HTML | SHA-256 seal |
| `audit` | Independent audit pack (HTML + MD + JSON) with 30 adversarial checks and a negative control | See below |
| `install-skills` | Copies the 25 skills into `.claude/skills`, `.cursor/skills`, `.agents/skills`, `.gemini/skills` or `.github/skills`; refuses to overwrite | Copy verified, host activation not verified |
| `serve` | Localhost-only, read-only report endpoint with bearer token | Not a public service |

Exit codes: `0` ok · `1` audit gaps or failed verification · `2` usage or input error.

### Independent-audit stance

The audit report is generated by the same tool it audits, so it is a **self-assessment with reproducible evidence**, not third-party certification. You can verify it yourself: clone, run `npm test`, run `npm run audit`, and compare the SHA-256 values. We describe what was **not** tested in every report (native IDE activation, live GitHub state, running target-repository tests, other operating systems, adoption).

## What it will never do

- Open, comment on, assign, label or merge anything on GitHub.
- Run `npm install`, `make`, `pip`, or any script found in a repository, README or issue.
- Treat issue or README text as instructions (it flags instruction-like text and moves on).
- Say a test passed because a person, a file or a badge said so.
- Infer that a maintainer *wants* a contribution just because a label or an issue is public.
- Collect telemetry or make network calls. (`serve` binds `127.0.0.1` only and is optional.)

## Agent skills (instruction files, not autonomous processes)

20 specialist roles (Prime, Repository Cartographer, Policy Guardian, Setup Doctor, Toolchain Scout, Issue Pathfinder, Skill Matcher, Scope Architect, Learning Coach, Test Mentor, Patch Reviewer, PR Readiness, Maintainer Respect, Security Boundary, Evidence Ledger, Accessibility Mentor, Docs Pathfinder, Community Steward, IDE Bridge, Release Auditor) and five capability skills (`repo-onboard`, `good-first-issue`, `setup-check`, `test-first-coach`, `pull-request-check`). A `SKILL.md` file is text a host agent may follow. **It is not an independent AI process, and copying it is not proof it activates in your IDE.** Native activation in each host is **not yet verified**: see [IDE compatibility](docs/IDE_COMPATIBILITY.md).

```bash
npx contribsutra-ai install-skills --ide claude --project .
```

## FAQ

**Is this a GitHub bot or an AI that writes my pull request?** No. It prepares you and a reviewer. You write the change and decide whether to submit.

**Does it need an API key or internet?** No. Everything runs offline on Node.js 20+.

**Why does it decline some "good first issue" issues?** A label can be stale. Closed, assigned, locked, security-related, instruction-injected and very large issues are declined with a reason; unlabelled issues carry an "ask first" warning.

**Can maintainers use it?** Yes: run `scan` and `audit` on your repository to see which onboarding files, policies and CI are visible to newcomers.

**Is it affiliated with GitHub, Anthropic, Cursor, OpenAI or Google?** No. Product names are used only to describe compatibility targets.
